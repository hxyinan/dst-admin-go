修复游戏内 Runtime 加载失败与重复采集报错，并加入本机和 Agent 的自动维护。

- 修复 `BOOTSTRAP_UNAVAILABLE`：采集脚本改用游戏允许的 PersistentStorage 路径，同时调整长命令文件位置。
- 控制端启动、Agent 升级或重新接入后，自动检查已启用的 Runtime。运行中的世界热加载并验证新实例与采集结果，停止的世界在下次启动时加载；正常升级无需重启世界。
- 更新前保留受管脚本备份，激活失败时尝试恢复原文件和旧实例。保留用户自定义 Lua、未知文件及游戏存档；已卸载的 Runtime 不会被自动装回。
- 修复更新超时后的异步回调、旧进程健康文件和暂停世界的判断，避免误报成功、覆盖后续实例或重复加载。繁忙的世界会暂缓维护并自动重试。
- 采集模块异常时减少无效刷新和控制台探针，按失败次数延长重试间隔；旧数据保持过期标记。手动刷新未执行时显示实际失败原因。
- Runtime 状态页增加自动维护进度、失败原因和修复重试入口，提供中英文说明。
- 构建工具链升级至 Go 1.26.10，修复标准库证书校验漏洞 GO-2026-6809。

**从 v1.3.0 升级：** 在 **系统设置 → 软件更新** 更新控制端；独立 Agent 在 **机器管理** 中分别升级。两端都更新后，系统自动维护配套 Runtime 2.4.11。无需修改 `server.ini`、删除存档或重新生成世界。若受管脚本曾被手动修改，请先检查 Runtime 状态中的冲突提示，再处理并重试。

Fixes in-game Runtime loading failures and repeated collection errors, with automatic maintenance for local worlds and Agents.

- Fix `BOOTSTRAP_UNAVAILABLE` by loading scripts from an allowed PersistentStorage directory and updating long-command document paths.
- Reconcile enabled Runtime installations after Controller startup and Agent upgrades or reconnections. Running worlds use verified hot activation; stopped worlds load the scripts on their next start. Normal upgrades do not restart worlds.
- Back up managed scripts before updates and attempt to restore both files and the previous instance if activation fails. Preserve custom Lua, unknown files and game saves. Explicitly uninstalled Runtime modules stay disabled.
- Guard delayed callbacks after timeouts, reject previous-process health, and retain healthy paused instances. Busy worlds defer maintenance and retry automatically.
- Back off unsuccessful refreshes and console probes while retaining stale-data markers. Manual refreshes that could not run report their actual failure.
- Show automatic maintenance progress, errors and repair actions in the Runtime status panel, with Chinese and English descriptions.
- Build with Go 1.26.10 to fix standard-library certificate validation vulnerability GO-2026-6809.

**Upgrade from v1.3.0:** update the Controller under **System settings → Software updates**, and upgrade standalone Agents separately under **Machines**. Once both sides are updated, matching Runtime 2.4.11 is maintained automatically. No `server.ini` changes, save deletion or world regeneration are required. If managed scripts were edited manually, inspect the Runtime conflict message, resolve the conflict and retry.
