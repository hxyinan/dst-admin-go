新增 **AI 助手与外部 MCP 接入**。AI 与页面共用 OpenAPI 管理接口，可检查运行状态、排查问题，并按管理员要求执行管理操作。

- 任意管理页面均可打开右下角的悬浮助手；**运维工具 → AI 助手** 提供完整对话、接入配置和操作记录。对话与草稿按账户保存在当前浏览器，切页、切换房间和刷新后保留，处理过程默认折叠。
- 支持兼容 OpenAI Chat Completions 工具调用的模型。查询轮数、调用次数和单轮总时限可在页面修改；外部 AI 可通过 Streamable HTTP MCP 或带 Bearer 密钥的 REST API 接入。
- 通过共享 OpenAPI 发现和调用房间、世界、模组、玩家、备份、定时任务、游戏安装更新、节点、通知及系统设置等管理接口。常用查询直接提供分片 CPU/RSS、真实玩家、已配置模组和实际任务结果。
- 页面与 AI 共用自动备份配置：可启用、修改或暂停计划，并返回实际生效状态和下次执行时间。新计划默认每天 04:00（北京时间），保留最近 7 份；未指定的已有设置保持原值。
- 支持附件上传、结果下载和私密输入；密码、密钥及验证码通过加密引用传递，避免直接进入模型上下文。操作保留页面相同的身份、部署角色、参数和 Runtime 校验。
- 明确区分模型额度不足、超时和连接错误。短暂故障仅重试模型请求；已执行的管理操作不自动重发，模型回复中断后仍保留真实回执和可获取的任务状态。
- 修复热备份屏障误用旧运行时版本、导致正常分片回执被拒绝并超时的问题。校验现在跟随当前运行时版本，并显示明确的不匹配原因。

**从 v1.2.8 升级：** 在 **系统设置 → 软件更新** 更新控制端和内置前端，无需重新拉取镜像。配置、数据库和游戏存档保留。AI 默认关闭；启用后需配置可用的模型服务，模型服务的费用与额度由其提供方管理。外部 MCP 客户端使用自己的模型，无需配置页面模型。

对话保存在浏览器，清理站点数据或更换浏览器后无法恢复；刷新会中断等待，已提交的任务可能继续执行。备份管理数据时，请同时保留配置目录下的 `ai/provider.key`，以便恢复加密的模型凭据。完整使用方式见 [AI 助手与 OpenAPI](https://github.com/lcy0828/dst-admin-go/blob/master/docs/ai-assistant.md)。

Introduces the **AI assistant and external MCP access**. AI and the UI share the OpenAPI management operations for inspection, troubleshooting and administrator-requested changes.

- Open the floating assistant from any management page, or use **Operations → AI assistant** for the full conversation, connections and activity history. The browser retains conversations and drafts per account across navigation, room changes and reloads. Execution details stay collapsed by default.
- Connect models that support OpenAI Chat Completions tool calling. Configure tool rounds, call limits and the total turn timeout in the UI. External AI clients can use Streamable HTTP MCP or Bearer-authenticated REST APIs.
- Discover shared OpenAPI operations for rooms, worlds, mods, players, backups, automation, installation and updates, nodes, notifications and system settings. Compact queries include per-shard CPU/RSS, actual players, configured mods and real task results.
- The UI and AI share automatic backup configuration, including enable, edit and pause operations, effective status and the next execution time. New plans default to 04:00 daily in `Asia/Shanghai`, keeping seven snapshots; unspecified existing settings are preserved.
- Upload attachments, download results and supply private inputs. Passwords, keys and verification codes use encrypted references instead of model-visible plaintext. Operations retain the same identity, deployment-role, validation and Runtime checks as the UI.
- Distinguish model quota exhaustion, timeouts and connection failures. Transient failures retry only the model request; management operations are not automatically replayed. Actual receipts and available job status remain visible when model generation fails.
- Fix hot-backup barriers rejecting valid shard receipts because their expected runtime version was outdated. Validation now follows the shared runtime version and reports mismatches explicitly.

**Upgrade from v1.2.8:** update the Controller and embedded UI under **System settings → Software updates**, without pulling a new image. Configuration, database and game saves are preserved. AI is disabled by default and requires an available model service for browser chat. Model billing and quota are managed by its provider. External MCP clients use their own models and do not require a configured browser-chat model.

Chat history is browser-local and cannot be recovered after clearing site data or changing browsers. Reloading interrupts waiting; submitted jobs may continue. Include `ai/provider.key` from the configuration directory in management-data backups to restore encrypted model credentials. See the [AI assistant and OpenAPI guide](https://github.com/lcy0828/dst-admin-go/blob/master/docs/ai-assistant.en.md).
